# 一些思考

## sdtlb_tag_item

断言 PA[47] 为 0, 因为 PA[47] 指 IO 空间, 内存池化只处理 MEM 空间, 不处理 IO 空间

当 wr_pa_up 为 0 时, 表示的一定是页式代换 (1GB), 此时 wr_pa_base 可以为任意值
当 wr_pa_up 非 0 时, 表示的一定是段式代换, 此时 wr_pa_base 虽然依然可以为任意值, 但断言 wr_pa_base 与 wr_pa_up 的组合不能越界

如果本来 mem 里是一张段式代换的 SDT_L1 表, 假设前 16G 为有效; 如果之后 OS 把这个表换成了后 16G 为有效, SDTLB 如何处理? (OS 通过 IOR::SDecoder_IS ,根据 PA 地址进行无效化?)

断言 SDTLB 里没有冲突的表项? (似乎很难实现, 也许写在 monitor 里更好?)

CORE 内 TLB 只有 tlb_tag.valid 是 ff, 其他 tlb_tag 字段以及 tlb_data 都是 latch, 是否沿用?

需要断言 128bit 的 hit vector 是宽松独热码 `$onehot0`

s_pfn 是 [17:0] 的, 所以本地 import 的内存空间不包括 IO 空间, 远程 export 的空间可以包括 IO 空间?
