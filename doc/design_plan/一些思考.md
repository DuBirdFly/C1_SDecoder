# 一些思考

## sdtlb_tag_item

断言 PA[47] 为 0, 因为 PA[47] 指 IO 空间, 内存池化只处理 MEM 空间, 不处理 IO 空间?

s_pfn 是 [17:0] 的, 所以本地 import 的内存空间不包括 IO 空间, 远程 export 的空间可以包括 IO 空间?

什么时候软件进行无效化操作?
(如果本来 mem 里是一张段式代换的 SDT_L1 表. 假设前 16G 为有效, 如果之后 OS 把这个表换成了后 16G 为有效, SDTLB 如何处理?)
(OS 通过 IOR::SDecoder_IS ,根据 PA 地址进行无效化?)

如何断言 SDTLB 里没有冲突的表项?
(比如之前已经有一条 entry 了, 之后软件清掉了, 但忘记进行 inv 操作, 之后又写入一条同内容 entry, 就有可能有冲突)
(似乎很难实现, 也许写在 monitor 里更好?)

tlb_*_item 使用 ff 还是 latch?
(CORE 内 TLB 只有 tlb_tag.valid 是 ff, 其他 tlb_tag 字段以及 tlb_data 都是 latch, 是否沿用?)
(或者其他都用无 rst_n 的 ff?)
(或者 tlb_data 用 ram?)

tlb 的替换策略选什么?
CORE 内的 tlb 里是 "伪随机替换", 目前 SDTLB 里目前是 "自增条目轮转替换"

tlb_data_item.grn 感觉没有意义, 有哪里需要用到吗?
