# md 文件编写规范

适用范围: `doc/` 目录下的全部 Markdown 文档 (设计方案, 评审记录, 使用说明等).

目的: 统一文档的表达形式, 让文档可 diff, 可评审, 平台无关, 并避免仓库被无意义的位图撑大.

## 一. 图表

### 总原则

1. **优先使用 Mermaid**: 图表以文本形式存在, 可版本管理, 可 diff, 可评审, GitHub / GitLab / 主流编辑器预览均可原生渲染.
2. **Mermaid 不适合时, 使用文件型图片** (PNG / SVG), 具体场景见 1.3.
3. 同一张图只保留一种形式, 禁止既贴位图又保留一份 Mermaid 源码.

### Mermaid 的适用范围

| 图的内容 | 推荐语法 | 备注 |
| --- | --- | --- |
| 流程, 流水线, 数据流 | `flowchart` | 最常用; 层次用 `subgraph` 分组 |
| 模块框图, 总线层次 | `flowchart` / `block-beta` | 走线复杂时改用文件型图片 |
| 交互时序, 请求应答 | `sequenceDiagram` | 信号级波形不适用, 见 1.3 |
| 状态机, 事务生命周期 | `stateDiagram-v2` | TLB 状态, 事务状态等 |
| 类结构, 接口关系 | `classDiagram` | |
| 表项与数据结构关系 | `erDiagram` | 精确位域布局改用文件型图片 |
| 版本演进, 分支关系 | `gitGraph` | |
| 排期计划 | `gantt` | |
| 占比分布 | `pie` | |
| 方案脑图 | `mindmap` | |

写法要求:

- 围栏语言固定写 `mermaid`, 不要用 `mmd`, `mermaidjs` 等别名.
- 节点文字含空格, 括号, 斜杠等符号时用引号包裹, 例如 `A["Home 侧 (SMMU)"]`.
- 单张图建议不超过 25 个节点, 超出则拆分, 或改用文件型图片.
- 不要在节点里塞长句, 节点用短标签, 语义放到图注里说明.
- 不要依赖过新的 Mermaid 语法: 各平台渲染版本滞后, 可用下面的方式查询当前平台支持的版本, 不确定的语法先在目标平台验证.

  ```mermaid
  info
  ```

### 改用文件型图片的场景

- 数字波形与信号级时序: clk / valid / ready 握手, 复位时序, 流水线节拍.
- 寄存器位域, 表项字段布局, 报文格式等需要精确到 bit 的排版.
- 仿真波形, 综合与布局结果, 版图, 微架构模拟截图.
- 走线与分组复杂, 需要精细控制的模拟框图.
- 从 Visio / draw.io / Excel / 仿真工具导出的既有图.
- 数据图表: 带宽, 命中率, 延迟等曲线与柱状对比.
- 照片, 扫描件, 外部资料截图.

说明: 这些场景虽然存在 WaveDrom, Bytefield 等文本 DSL, 但它们在默认渲染链路 (GitHub, 常见编辑器预览) 中不会自动渲染, 会出现 "有的平台能看图, 有的平台是代码块" 的不一致. 因此本仓库统一收敛为文件型图片.

### 文件型图片规范

#### 目录与命名

```text
doc/<文档名>/
├── <文档名>.md
└── image/
    └── <文档名>/
        ├── fig-tlb-entry-layout.svg
        └── fig-address-translation-flow.svg
```

- 图片放在与 Markdown 同级的 `image/<文档名>/` 目录下, 用相对路径引用, 保证 clone 后离线可看.
- 文件名语义化, 小写加连字符, 禁止 `image1.png` 这类无信息命名.

#### 引用格式

```markdown
![TLB 表项字段布局](image/<文档名>/fig-tlb-entry-layout.svg)

<img src="image/<文档名>/fig-pipeline.svg" width="720" alt="SDecoder 流水线结构">

图 1: SDecoder 流水线结构. 说明这张图要传达的结论.
```

- `alt` 必填, 写清 "这张图是什么", 不要写 "图片".
- 正文中用 `图N: 标题. 说明` 的形式给出图注, 编号在全文内连续.
- 需要控制显示宽度时用 `<img width="...">` (本仓库 markdownlint 已放开行内 HTML).
- 优先 SVG; 必须用位图时选 PNG, 不要用 JPG (示意图含文字, JPG 会有压缩伪影).
- 禁止用 base64 data URI 内嵌图片.
- 暗色主题下白底图片很刺眼: 优先导出透明背景或适配深色的 SVG; 确需两套时用 `<picture>` 配合 `prefers-color-scheme`.

## 二. 标点符号

### 基本约定

**文档中一律使用英文 (半角) 标点, 不使用中文 (全角) 标点.**

原因: 半角标点在各种字体与渲染环境下宽度一致, 便于 diff 与检索, 也避免中英文混排时行距跳动.

### 对照表

| 用途 | 使用 | 不使用 |
| --- | --- | --- |
| 逗号 | `,` | `，` |
| 顿号 | `,` | `、` |
| 句号 | `.` | `。` |
| 冒号 | `:` | `：` |
| 分号 | `;` | `；` |
| 问号 | `?` | `？` |
| 叹号 | `!` | `！` |
| 圆括号 | `()` | `（）` |
| 方括号 | `[]` | `【】` |
| 引号 | `"..."` 或 `'...'` | `“...”` 或 `‘...’` |
| 省略号 | `...` | `……` |
| 破折号 | `-` 或 `--` | `——` |
| 书名号 | 直接写名称, 或加引号 | `《》` |

### 说明

- 本规范文档自身同样遵守上述约定.
- 代码块与行内代码 (反引号包裹的内容) 内的符号保持原样, 不做转换.
- 引用外部原文时 (如标准, 手册, 论文的正式标题), 保持原文写法.

## 三. 检查

排版类问题交给 markdownlint, 规则集与命令说明见 [`doc/dev/markdownlint/README.md`](dev/markdownlint/README.md).
改动后**在仓库根目录**执行:

```bash
markdownlint-cli2 "doc/**/*.md" --config ./.config/.markdownlint.jsonc
```

`--config` 必须带上: markdownlint-cli2 不向上级目录查找配置, 省略后会退回默认规则.
注意: 该工具只覆盖排版规则 (空行, 列表, 围栏, 行宽等), 图表形式与标点约定仍需人工评审.
